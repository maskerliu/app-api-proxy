### 0.2 编号与状态

- 卡号格式 `R1C-xx`，与评审文档中的关注点 `R1-7`～`R1-13` 不冲突。
- 状态取值：`待开始 / 进行中 / 待联调 / 已完成 / 已阻塞`。
- 每张卡完成后必须回填：实际工时、偏差原因、遗留项。

### 0.3 统一约束（所有卡适用）

1. **纯函数边界**：`src/shared/**` 不得依赖 axios、vant、Node 内置模块；Matcher / 派生分析不得做 IO。
2. **契约先行**：M0 结束前冻结 `MockMatchRule`、错误码表、指纹规范；UI 只允许对冻结契约编码，禁止各自定义 DTO。
3. **失败不抛异常**：匹配未命中返回 `{ matched: false, miss }`，不得用异常控制流程；只有入参非法才抛错。
4. **热路径不构造字符串**：miss 的廉价评分阶段禁止拼接期望/实际值，只有 top-1 物化时才构造。
5. **热路径不读库**：匹配只读内存快照与响应 LRU，禁止在 `MockService.mock` 内调用 PouchDB。
6. **Method 哨兵值 `'ANY'`**：不得用空串表示任意方法；归一化层缺失 method 时输出 `''`，进入匹配前统一转 `'ANY'`。
7. **可解释**：任何自动放宽（忽略键、Path 参数化）必须带来源与证据，且可撤销。
8. **脱敏**：`sign`、`token`、`authorization`、`cookie` 的值在解释、诊断、日志中一律遮蔽为 `***`。
9. **不静默截断**：5,000 条只提示，10,000 条拒绝启用，禁止只加载前 N 条。
10. **文案**：新增文案同时补 `src/lang/zh-CN.ts` 与 `src/lang/en.ts`，不允许硬编码中文。
11. **完成定义（DoD）**：实现 + 单测 + `tsc` 通过 + 对应 AC 手工验证 + 无新增 console 报错；缺一不算完成。

#### R1C-01 · 共享匹配模型与请求元数据

| 项 | 值 |
|---|---|
| 负责人 / 工时 | Dev A / 1.0 人日 |
| 依赖 | 无 |
| 里程碑 | M0 |
| 文件 | `src/shared/mock.models.ts`（新建）、`src/shared/proxy.models.ts` |

**目标**：一次性冻结匹配相关类型与命中元数据，主进程与渲染层共用同一套结构，避免后续双端漂移。

**实现要点**
- 新建 `mock.models.ts`，定义 `MockMatchLevel`、`PathMatchType`、`MockQueryOperator`、`MockQueryCondition`、`MockQueryMatch`、`MockHeaderCondition`、`MockHeaderMatch`、`MockBodyMatch`、`MockMatchDerivation`、`MockMatchRule`、`MockMatchExplain`、`MockMissDiagnostic`、`MockMatchWarning`、`MockHitMeta`。
- `MockRecord` 扩展 `match?: MockMatchRule`、`matchInvalid?: string`、`matchFingerprint?: string`；`url` 改为可选但保留。
- `ProxyRequestRecord` 新增 `mock?: MockHitMeta`，供 `REQUEST_END` 携带命中/未命中元数据（T00-4）。

- `MockHitMeta` 与 UI 渲染字段一一对应，禁止 UI 侧再定义局部接口。

**验收**
- [ ] 主进程、渲染层均可 `import type { MockMatchRule, MockHitMeta }`，`tsc` 无循环依赖告警。
- [ ] `createDefaultMatch` 快照测试覆盖「有 Query / 无 Query / 缺 method」三种输入，缺 method 输出 `'ANY'`。
- [ ] 类型中 `priority` 允许 `null`，`body.mode` 允许 `'ignore'` 且仅此一种。
- [ ] `ProxyRequestRecord.mock` 为可选，旧数据读取不受影响。

**注意**
- 不搬迁既有 `MockRecord` / `MockResponseDef`，只扩展，减少无意义改动面。
- `MockMatchRule.version` 固定为 `1`，为后续 schema 演进留位。
- 时间、ID 等无副作用工具不放进 `mock.models.ts`，避免 shared 引入运行时依赖。

#### R1C-02 · 校验器、错误码与指纹

| 项 | 值 |
|---|---|
| 负责人 / 工时 | Dev A / 0.5 人日 |
| 依赖 | R1C-01 |
| 里程碑 | M0 |
| 文件 | `src/shared/mock.validation.ts`、`src/shared/mock.errors.ts`（新建） |

**目标**：保存、导入、迁移前用同一套规则拒绝非法条件；错误码集中可查，UI 可直接映射文案；提供顺序无关的匹配指纹，替代 URL 唯一键。

**实现要点**
- 新建 `mock.errors.ts`，集中导出错误码常量与 `MockErrorCode` 联合类型：`methodInvalid`、`hostInvalid`、`pathTypeInvalid`、`pathEmpty`、`pathRegexInvalid`、`pathRegexTooLong`、`pathRegexUnsafe`、`queryOperatorInvalid`、`queryValueMissing`、`headerNameInvalid`、`headerValueInvalid`、`bodyModeUnsupported`、`priorityInvalid`、`matchMissing`、`matchDuplicate`、`recordTooMany`、`migrationFailed`。
- `validateMatchRule(match)`：Method 白名单或 `'ANY'`；Host 去协议/路径后校验，支持 `*.example.com`、IPv6；Path 非空、正则长度 ≤ 200 且可编译；Query 操作符与值匹配；Header 名符合 RFC 且值无 CRLF；`body.mode !== 'ignore'` 直接报 `bodyModeUnsupported`。
- `canonicalMatch(match): string`：生成顺序无关的规范串；Query 条件按 `key → operator → value` 排序，Header 按小写键排序，`ignoreKeys` 去重排序；**排除** `level`、`priority`、`enabled`、`derivation`、名称与响应。
- 指纹只在主进程哈希：`createHash('sha1').update(canonicalMatch(match)).digest('hex')`，shared 层不引入 Node 内置模块。
- `normalizeMatchRule(match)` 补齐默认值，保证旧文档读出后可直接进入 Matcher。
- `validateMockRecord` 中的 `urlEmpty` 改为条件必填：仅有 `match` 时不再要求 URL。

**验收**
- [ ] 同一组条件换顺序、换 `ignoreKeys` 顺序，指纹一致。
- [ ] `allowExtra`、`multiValue`、Path 类型、Method 任一不同，指纹不同。
- [ ] 含 `body.mode=jsonSubset` 的记录校验失败，错误码为 `bodyModeUnsupported`。
- [ ] 有 `match` 无 `url` 的记录可保存；两者都缺时返回 `matchMissing`。
- [ ] AC-R1-19、AC-R1-20 的校验前置条件成立。

**注意**
- 指纹只描述「匹配什么」，不描述「返回什么」；响应或变体变化不得改变指纹，否则重复检测会误报。
- 错误码是 UI 文案的键，新增码必须同时补 `zh-CN` / `en` 两条文案。

### M1 Matcher 核心（7.0 人日）

#### R1C-04 · NormalizedRequest 归一化

| 项 | 值 |
|---|---|
| 负责人 / 工时 | Dev A / 2.0 人日 |
| 依赖 | R1C-01 |
| 里程碑 | M1 |
| 文件 | `src/main/service/mock.matcher.ts`（新建） |

**目标**：一次归一化，供所有候选记录复用；统一 Host、Path、Query、Header 的边界语义。本卡是后续所有匹配语义的地基，边界用例必须先写测试。

**实现要点**
- 入参 `{ method?, url, headers? }`；`req.url` 已是挂载在 `/_proxy` 之后的相对地址，无需再手工剥离前缀。
- 输出结构：

```ts
interface NormalizedRequest {
  method: string                       // 大写，缺失为 ''
  host: string                         // 小写，去协议/路径/端口
  port: number | null                  // 未显式声明为 null（任意端口）
  path: string                         // 以 / 开头，已消除点段与重复斜杠
  query: Map<string, { values: string[]; hasEquals: boolean }>
  headers: Map<string, string[]>       // 键小写，值 trim
  rawUrl: string
}
```

- Query **不使用 `URLSearchParams` 直接取值**：手工按 `&` 切分，保留 `?a`（无等号）与 `?a=`（空值）的区别；`+` 先替换为空格再 `decodeURIComponent`，解码失败保留原文；重复键合并为数组。
- Path 用 `new URL(url, 'http://placeholder')` 解析，再用 `decodeURI`（不是 `decodeURIComponent`）解码，避免 `%2F` 被还原成路径分隔符；最后 `replace(/\/{2,}/g, '/')` 合并重复斜杠。
- 尾斜杠不在归一化阶段删除，保留原值，由 `ignoreTrailingSlash` 在匹配时决定。
- Host：先取 `x-mock-host`，缺失回落真实 `host` 头；两者都缺失为空串（任意 Host）。显式端口解析需兼容 IPv6 `[::1]:8080`。
- Method 统一大写；不做 HEAD→GET 回退；缺失时输出 `''`，由调用方转 `'ANY'`。
- 归一化结果在单个请求内只计算一次，禁止在每条候选记录上重复解析。

**验收**
- [ ] AC-R1-03：有/无 `x-mock-host` 均能得到正确 Host。
- [ ] AC-R1-14：重复键保留为数组，`?id=1&id=2` 可区分。
- [ ] AC-R1-15：`%E4%B8%AD` 与中文原文、`+` 与 `%20`、尾斜杠差异均归一化一致。
- [ ] 单测覆盖：无 Query、空 Query、`?a`、`?a=`、`?a=1&a=2`、非法百分号编码、IPv6、显式端口、`%2F` 保留、重复斜杠。

#### R1C-05 · Path 四类型匹配

| 项 | 值 |
|---|---|
| 负责人 / 工时 | Dev A / 1.0 人日 |
| 依赖 | R1C-04 |
| 里程碑 | M1 |
| 文件 | `src/main/service/mock.matcher.ts` |

**目标**：实现 `exact / prefix / glob / regex` 四种 Path 语义，并把正则风险控制在可接受范围。

**实现要点**
- `exact`：按 `pathIgnoreCase`、`ignoreTrailingSlash` 比较。
- `prefix`：按同样选项做前缀比较。
- `glob`：转正则时先转义元字符，`*` → `.*`（含 `/`），`?` → `[^/]`，`\` 转义下一个字符；整段锚定。
- `regex`：引擎自动加 `^...$`；编译前截断被匹配 Path 到 2,048 字符；编译结果按 pattern 缓存。
- 正则长度 ≤ 200；保存时拒绝明显高风险模式（嵌套量词，如 `(a+)+`、`(.*)*`），但不承诺穷举。
- 暴露 `pathSpecificity(type)`：`exact=4 / prefix=3 / glob=2 / regex=1`，供排序使用。

**验收**
- [ ] AC-R1-04：`/v1/users/*` 命中 `/v1/users/10086`。
- [ ] `?` 不跨 `/`、`*` 跨 `/`、转义字符按字面匹配。
- [ ] 非法正则保存失败且错误可读；运行期编译失败按不命中处理，不崩溃。
- [ ] Path 超过 2,048 字符时被截断后再匹配，不抛异常。

**注意**
- glob 的 `*` 与 regex 的 `.*` 都必须锚定整段，禁止子串命中。
- 编译缓存必须有上限（默认 512），避免用户频繁编辑导致正则对象泄漏。

#### R1C-06 · Query / Header 条件匹配

| 项 | 值 |
|---|---|
| 负责人 / 工时 | Dev A / 1.0 人日 |
| 依赖 | R1C-04 |
| 里程碑 | M1 |

**目标**：实现 PRD 的 Query 五条语义与 Header 条件匹配，保证「该松的松、该紧的紧」。

**实现要点**
- Query `mode=ignore` 直接通过；`mode=match` 时：
  1. 先剔除 `ignoreKeys`；
  2. 所有 `conditions` 按 AND；
  3. `allowExtra=true` 忽略未声明键，`false` 时存在未声明键即失败；

  5. `multiValue=any` 任一值满足，`all` 所有值满足。

- 空值与缺省必须可区分：`exists` 两者都通过，`equals ''` 只匹配 `?a=`。
- Body：`mode !== 'ignore'` 的记录不进入 Matcher，由校验/迁移层标记为无效。
- 返回条件级结果 `{ dimension, passed, conditionIndex }`，供解释与诊断复用，避免二次比对。

**验收**
- [ ] AC-R1-13：标准档额外参数仍命中，严格档不命中。
- [ ] AC-R1-14：`id=1&id=2` 在 `any` 下命中、`all` 下不命中。

#### R1C-16 · 匹配快照、增量失效与规模护栏

| 项 | 值 |
|---|---|
| 负责人 / 工时 | Dev A / 1.5 人日 |
| 依赖 | R1C-07、R1C-11、R1C-12 |
| 里程碑 | M4 |
| 文件 | `src/main/service/mock.cache.ts`（新建） |

**目标**：把「每次请求都遍历记录」变成「分桶 + 预过滤 + 记忆化」，且保存后不必全量重建。

**实现要点**
- 每个场景一份编译结果（不含响应体）：

```ts
interface CompiledRuleSet {
  version: number
  exactPathMap: Map<string, CompiledRecord[]>
  prefixList: CompiledRecord[]      // 按前缀长度降序，等价 trie 的前缀优先语义
  globList: CompiledRecord[]
  regexList: CompiledRecord[]
  manualPriorityList: CompiledRecord[]
  recordCount: number
  compiledAt: number
}
```

- 编译时过滤 `enabled=false` 与 `matchInvalid`；预编译 glob/regex 正则，避免每次请求重复编译。
- 匹配顺序：手动优先级组 → exact → prefix → glob → regex；每个桶内先按 Method + Host 预过滤，再逐个校验 Query/Header。
- **增量更新**：`upsert(record)` / `remove(recordId)` 直接改桶，不重建全量；仅当规则版本不匹配或记录数变化超过 10% 时全量重建。
- LRU 记忆化：key = `method|host|path|规范化 query|相关 header 哈希`，容量 1,000；记录写入/删除时按 recordId 精确清除相关键，无法定位时整体清空。
- 失效时机：保存/删除/导入/启用切换/迁移完成；全部经 R1C-12 的保存队列回调触发。
- 上限：> 5,000 返回 `{ warn: 'splitRecommended' }`，但全部参与匹配；> 10,000 拒绝启用并返回 `recordTooMany`，不允许静默截断（主进程强制，不依赖 UI）。
- 对外只暴露 `getCompiled(ruleId)`、`upsert`、`remove`、`invalidate(ruleId)`、`getLimitState(ruleId)`。

**验收**
- [ ] AC-R1-08：1,000 条、90% miss 的基准达标（见 R1C-27）。
- [ ] 保存 1 条记录后下一次请求立即使用新规则，且不触发全量重建（用编译计数断言）。
- [ ] 连续保存 100 条，编译次数 ≤ 1 次全量 + 100 次增量。
- [ ] AC-R1-18：6,000 条提示拆分但全部参与；10,001 条在服务层拒绝启用，绕过 UI 也生效。
- [ ] 缓存命中时匹配耗时 ≤ 0.3ms（单测计时，允许 CI 抖动放宽）。

**注意**
- 不要把 `matchWarnings` 计算放进每次请求；冲突扫描只在列表/保存时执行。
- 增量更新必须与保存队列同序，否则会出现「缓存超前于库」的脏快照。

## 7. 风险与应对

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 归一化细节反复 | 不同客户端对 `+`/`%20`、空值、IPv6 行为不一致 | C0 前冻结用例表，先写测试再实现（R1C-04） |
| 自动忽略过度 | `mockHitWithIgnoredKeys` 占比过高 | 语义键黑名单兜底；命中解释支持一键收紧 |
| 迁移阻塞启动 | 大库首次启动无响应 | 后台迁移 + URL 兜底 + 进度展示（R1C-13） |
| 迁移后重复指纹 | 用户首次保存即报重复 | 迁移期消解 + 报告逐条可见（R1C-15） |
| 保存与缓存竞态 | 保存后仍命中旧响应 | 保存队列 + 队列内触发失效（R1C-12/16/17） |
| 命中路径读库 | p95 无法进入 1ms | 匹配快照与响应 LRU 分离，benchmark 断言零 repo 调用 |
| UI 与后端条件模型漂移 | 档位切换后条件不一致 | 档位/摘要/校验全部复用 shared 纯函数 |
