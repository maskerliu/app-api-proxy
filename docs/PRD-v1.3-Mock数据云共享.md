## 1. 背景与目标

### 1.1 背景

R4 已经把「规则可以离开这台机器」做完了：JSON 规则包的导出、预览、导入、冲突三策略、取消与脱敏都能从界面用。剩下的是**换机与协作**这两件事，它们今天的形态是「用户自己拷一个 `.json`」：

1. **换机/重装恢复**没有可信路径。用户知道数据在 `%APPDATA%\AppApiProxy\biz_storage\Mock.Rules`（使用说明 9），但 PouchDB 目录直接拷贝会带上 schema 版本与迁移报告，官方建议的恢复手段其实只有「导出再导入」，而导出要手点、文件要自己存到某处。
2. **两台机器之间**没有同步：家里改了，公司还是旧的，只能重新导出导入一遍，且不知道该合并到哪个场景。
3. **给同事**只能发文件。文件会过期、会传错版本、对方不知道是不是最新。

调研稿已经给出结论：不建自有云，做「自带存储」（BYO），把「云」退化成「一个用户自己控制的目录或一个只读 URL」。本文档在这个结论之上把**本期到底交付哪几件事**定成可开发的需求，并且按当前代码事实修正了三处会改变范围的判断（3.3）。

### 1.2 本期目标

| 目标 | 说明 | 对应需求 |
|---|---|---|
| O1：让备份成为一条动作 | 一次点击把全部场景写成远端可读的一整套文件，进程在任何一步被杀都不会留下读不了的半包 | C1 C2 |
| O2：让换机恢复不需要手点导出 | 指向同一个目录，在另一台机器上读出、预览、按场景选择恢复，恢复后下一个真实请求命中 | C3 |
| O3：让「给同事」变成一个地址 | 订阅任意只读 URL，先看清有什么、变了多少条，再决定导入哪些 | C4 |
| O4：让「不上云」这个卖点不被自己削掉 | 默认关闭、可完全离线、关闭后零对外请求、云端只可能拿到脱敏后的内容 | C5 C6 |

不做目标：双向同步与冲突自动合并（依赖删除语义，本期只有单向写与显式读，见 11.3）。写进目标表的东西必须有对应需求卡，没有卡的能力不在本期。

### 1.3 成功指标

| 指标 | 目标 | 本期可测吗 |
|---|---|---|
| 备份 5,000 条记录（R4 实测过的最大形态）到本地 SSD 目录 | ≤ 60s | 可测：集成用例计时 |
| 恢复完成后下一个真实请求命中，且匹配不回读库 | 100% | 可测：沿用 R4 那条行为断言 |
| 云共享关闭时的对外 HTTP 请求数（版本检查除外） | 0 | 可测：本机假远端计数 |
| 远端半包/被手改的文件被拒读而不是导入成功 | 100% | 可测：用例构造缺片与改字节 |
| 首次备份成功率（真实网盘用户） | ≥ 99% | **本期不可测**——PRD-v1.1 第 8 章本地埋点整体未接入，没有采集入口；立项时不要把这格当成已达标 |
| 换机恢复耗时（重装到规则可用） | ≤ 5 分钟 | 半自动：手工演练计时，无自动化 |

### 1.4 范围

**本期包含：**

- 远端目录通道（读写）：本地磁盘目录与网盘客户端的同步目录同等对待，不实现任何网络协议。
- 备份动作：全部场景 → 场景级文件 + manifest，原子写、校验和、分片、内容未变则跳过上传。
- 恢复动作：读远端 → 预览差异 → 按场景选择 → 走 R4 既有导入管线落库。
- URL 订阅通道（只读）：GET 一个 `.json`，裸包与本产品端点包装形态都能吃。
- 远端错误分类、双语文案、设置页分区 UI。
- 打包与三平台冒烟（桌面独占能力，Web 版不出现入口）。

**本期不包含（附原因）：**

- **双向自动同步、后台调度、冲突自动合并**——需要删除墓碑；没有墓碑的自动同步会把「在一台机器上删掉」变成「被另一台机器复活」，或者用整包覆盖假装同步、静默丢数据。
- **WebDAV 写通道与一切需要账号口令的协议**——坚果云/Nextcloud/群晖的实现参差是验证成本而不是代码成本；连带**本期不做凭据安全存储**（本期两条通道都不需要口令：目录通道由网盘客户端自己鉴权，URL 订阅是匿名只读）。口令/token 的安全存储是 Phase B 的前置件，调研稿 5.5 与 3.2 缺口那两条一起挪过去。
- **公开端点的口令加密（scrypt + AES-GCM）**——同属 Phase B。
- **Web 版云共享**——浏览器没有文件系统，网盘不放通跨域；桌面独占，Web 版连入口都不渲染（不是点了报错）。
- **单场景备份档**——远端布局是场景级的，技术上支持，但本期只做「全部场景」一次备份：额度按月度量算，选择性上传会让用户以为省了流量而实际反复重写 manifest。恢复侧可以选场景子集（读侧便宜）。
- **官方代管存储（R2 之类）**——与「零运维 + 数据主权在用户」直接冲突，等 BYO 通道真实使用率出来再议。
- **云端在线编辑、评论、diff 视图、历史版本**（远端只保留最新提交 + 一份 `.bak`）。

> 与调研稿的范围差异只有一处实质性的：**凭据存储从本期移到 Phase B**（理由见 1.4 上一条与 3.3-D）。这同时把调研稿 C-A6 那张卡整张移出本期。

## 2. 用户与场景

| # | 故事 | 本期 |
|---|---|---|
| US-C1 | 换电脑/重装后，我用一个目录里的备份恢复全部 Mock 场景，恢复后第一个请求就该命中 | ✅ C2 C3 |
| US-C2 | 我把备份放在坚果云同步目录里，家里和公司的机器指向同一个目录 | ✅ C1 C2 C3 |
| US-C3 | 同事把规则包挂在内网静态目录/仓库上，我填一个地址，先看到「有什么、变了什么」，再选几条应用 | ✅ C4 |
| US-C4 | 我改了规则，应用自动同步到远端，两台机器不打架 | ❌ Phase C |
| US-C5 | 团队共用一个规则库，谁能改、改动留痕、要评审 | ❌ Phase C 之后 |

三个必须能被界面走通的场景：

1. **重装恢复**：新装应用 → 设置 → 云共享 → 选目录 → 从远端恢复 → 全选 → 导入 → 结果页跳场景 → 发请求命中。全程不出现「请先手动导出」。
2. **两台机器**：A 机备份 → 网盘客户端同步 → B 机恢复。B 机恢复时能看到「远端 12 个场景 / 上次备份由 A 机于 2 小时前生成」，并选择只恢复其中 3 个。
3. **给同事一个地址**：A 机把包放到内网 http 静态目录 → B 机订阅该地址 → 预览 → 应用。B 机不需要 A 机在线（这是与 3.3-A 那条现状的区别，见 Q6）。

### 3.3 本次核对新发现的四条事实（会改变范围或成本）

- **A. 调研稿 §5.6「被订阅端」不是待建能力，它今天就在，而且没有鉴权。** `GET /_appmock/exportMockPack?scope=all` 回的是 BizResponse 包裹的包文本，`redact` 与 `includeSource` 默认都是 `true`；`MainServer.startHttpServer` 用 `listen(port)`（不传 host ⇒ 绑所有网卡），全局中间件对每个响应写 `Access-Control-Allow-Origin: *`，`BaseRouter.route` 里没有任何鉴权/来源判定。**局域网里的另一台机器今天就能 GET 到一个人的全部场景。** 这不是 0.5 人日的新增功能，而是一条需要在立项时一并裁决的现状风险（Q6）：收紧它与「用手机浏览器打开 Web 版」这个既有用法直接冲突（Web 版就靠这个端点导出），不能顺手关掉。
- **B. 包格式里没有分片概念。** `MOCK_PACK_WRITE_BATCH` 是写库批大小，不是文件分片；`MOCK_PACK_MAX_FILE_BYTES` 是 50MB 的整包闸门。调研稿说的「单文件 ≤8MB 并分片」是净新增契约，不能声称复用 R4。
- **C. 包体不记录脱敏状态。** `MockPackV1` 只有 `format`/`version`/`appVersion`/`exportedAt`/`rules`；未脱敏只体现在文件名的 `-raw` 后缀上。⇒ 6.2 决定不在包里加 `redacted` 字段，改用 manifest 校验和兜（并写明代价）。
- **D. 脱敏的覆盖面比「明文不出本机」这句话窄。** `MOCK_SENSITIVE_HEADERS` 只有七个头名（authorization、cookie、set-cookie、proxy-authorization、x-token、x-access-token、x-auth-token），**host、path、query、响应体一概不脱敏**。上传到网盘的包必然暴露接口结构与响应内容。⇒ C6 的文案要求，以及 Q2 是否给 host 做可选脱敏。

## 4. 方案与选型边界

协议对照、各家额度上限的完整比较以调研稿第 3 节为唯一真源，本节只放**本期选了什么、为什么**，以及 2026-11-22 复测的数字。

### 4.1 本期通道

| 通道 | 本期 | 读 | 写 | 鉴权 | 备注 |
|---|---|---|---|---|---|
| 远端目录（本地盘 / 网盘客户端同步目录 / Syncthing） | ✅ | ✅ | ✅ | 无（客户端负责） | 唯一同时能备份与恢复的通道；零协议实现 |
| 只读 URL 订阅 | ✅ | ✅ | ✗ | 无（匿名可读） | 覆盖「同事挂了个地址」；额度与错误面比写通道小一个量级 |
| 通用 WebDAV 写通道 | Phase B | ✅ | ✅ | **需要凭据** | 各家 `MOVE`/条件请求实现参差，成本在验证不在代码 |
| 被订阅端（本机 8884） | 现状已存在，见 3.3-A 与 Q6 | ✅ | ✗ | 无 | 本期不把它当特性交付，也不顺手收紧 |
| GitHub Contents / Gist / R2 / Supabase / 自建 | 排除 | — | — | — | 理由见调研稿 3.1；OneDrive 的排除理由需按 4.3 修正 |

### 4.2 由额度倒推的三条硬约束（沿调研稿 3.2，本期落成正文要求）

1. **同步粒度 = 场景级文件**，一个场景一个文件，一次备份 = 1 次目录写 + N 次文件写。
2. **不做后台自动写**，本期只有用户显式触发的备份；同一份内容未变化则跳过上传（省额度的唯一手段）。
3. **单文件目标 8MB、超过分片、片数有上限**，超限拒绝并提示改用本地文件导出。

| GitHub Contents 写 ≤1MB | 本轮未取到官方明文页面 | 按最严口径处理，不影响本期（不选它） |
| Cloudflare R2 免费 | 10GB-month 存储、100 万 Class A、1,000 万 Class B、出口流量免费 | 一致；**补一句**：Class B 超出后计费，"无出口费"不等于"读免费" |
| Supabase 免费 | 1GB 存储、5GB 出口、最多 2 个活跃项目、**7 天不活动自动暂停** | 一致；暂停政策有专门文档页 |
| 国内可达性（本机 `curl` 实测，2026-11-22，同一台开发机） | `api.github.com` 200 / 0.97s；`raw.githubusercontent.com` **超时（10s）**；`dav.jianguoyun.com` 401 / 0.35s（可达，需口令）；`graph.microsoft.com` 200 / 0.33s；`api.onedrive.com` 401 / 1.15s；`api.dropboxapi.com` 超时；`www.googleapis.com` 超时 | **修正调研稿两处**：① OneDrive 不是「大陆不可达」，它的排除理由应改为「OAuth 要用户或我们自己注册应用身份，与 BYO 与零运维同时冲突」；② `raw.githubusercontent.com` 不可达本机实测坐实，「订阅 URL」这一条对 GitHub raw 用户就是不可用，文案不许暗示可用。 |

### 4.4 结论仍成立的两条

- BYO：数据主权在用户、零运维、天然免费；「本地优先、数据不上云」这条差异化只在**默认关闭 + 可完全离线 + 明文不出本机**三条同时写进需求时才守得住。
- 一旦自己做托管，成本、滥用、合规、可用性、以及「用户真实接口数据存在我服务器上」的定性变化同时上身——本期不碰。

## 6. 数据与契约

### 6.1 远端布局

```
<远端目录>/
  index.json                       ← manifest：最后原子替换，即提交点
  scenes/<sha1(ruleId) 前 12 hex>.json          ← 单场景包（MockPackV1，rules.length === 1）
  scenes/<同一个 12 hex>.part-2.json             ← 分片，按 manifest 里的顺序拼接
```

对调研稿两处修正：

1. **文件名用场景 `_id` 的哈希，不用场景名。** 用名字哈希会让「改名」换 key：旧文件留在远端，恢复时把改名前的场景当第二个场景导回来，产生副本。`_id` 稳定，名字放 manifest 里供人读。
2. 附带好处：网盘目录里的文件名不含任何项目/系统名，可读信息集中在 `index.json` 一个文件里。

### 6.2 manifest 字段

| 字段 | 用途 | 缺失/异常时的行为 |
|---|---|---|
| `format` / `version` | 兼容性只认 `version`；`version` 高于本产品支持值 → `remoteVersionTooNew` 拒读 | 不静默降级 |
| `createdAt` / `device` | 「谁在什么时候备份的」；`device` 为机器名哈希，不存真实机器名 | 缺失只影响显示，不影响读 |
| `scenes[]`：`key`/`name`/`records`/`bytes`/`sha1`/`shards[]` | 预览阶段不下载正文就能给统计与校验 | 清单与实际文件不符 → `remoteCorrupted` 拒读该场景 |
| `scenes[].skipped` | 记录本次没备份成的场景与原因，供结果页交代 | — |

**不加 `redacted` 字段**（3.3-C 的取舍）：云端包恒由云通道生成、恒脱敏，完整性由 manifest 的逐文件 sha1 保证；用户手工丢进备份目录的文件（含 `-raw` 未脱敏包）必然校验不过而被拒读——比字段级声明更强。代价要写明：**备份目录不是给用户手改的**，这条要进使用说明。

### 6.3 错误码第五组 `MOCK_SHARE_CODES`

| 码 | 触发 | 分类 |
|---|---|---|
| `remotePathMissing` | 目录不存在/未选择/被移除 | 配置 |
| `remoteUnreachable` | 网络盘不可达、连接超时、DNS 失败 | 网络 |
| `remoteNotFound` | 目录可读但没有 manifest / URL 404 | 不存在 |
| `remoteForbidden` | 权限不足、EACCES、URL 401/403 | 权限 |
| `remoteCorrupted` | 校验和不符、分片缺失、manifest 与实际文件不一致 | 内容损坏 |
| `remoteVersionTooNew` | `version` 高于支持值 | 兼容 |
| `remoteShapeUnknown` | 既不是裸包也不是本产品包裹 | 内容 |
| `remoteWriteFailed` | 写盘/重命名失败（含 ENOSPC） | 写 |
| `sceneTooLargeForCloud` | 单场景超过分片上限 | 上限 |
| `shareInProgress` | 已有备份任务 | 并发 |

### 6.4 新增常量（单源，`src/shared/mock.share.ts`）

| 常量 | 值 | 口径 |
|---|---|---|
| `MOCK_SHARE_MAX_FILE_BYTES` | 8 MiB | 单个远端文件目标体积，超过即分片；依据是坚果云 >10MB 条件请求那类限制（未复测项，取整留余量） |
| `MOCK_SHARE_MAX_SHARDS` | 4 | 单场景最多 4 片 ⇒ 云侧单场景硬上限 32MB，超过拒绝并提示本地导出 |
| `MOCK_SHARE_MAX_SCENES` | 300 | 单次目录列举按 750 项的服务商限制取一半余量，给冲突副本留位置 |
| `MOCK_SHARE_SKIP_UNCHANGED` | `true`（不可关） | 未变即跳过，额度约束的行为化 |
| `MOCK_SHARE_CONNECT_TIMEOUT` / `MOCK_SHARE_READ_TIMEOUT` | 10s / 60s | 60s 与 `update.runner.ts` 的 `DOWNLOAD_TIMEOUT` 同值 |

`MOCK_PACK_MAX_FILE_BYTES`（50MB）**不改成 8MB**：那是本地导入闸门，与云侧体积是两回事，合成一个常量会让「本地能导多大的包」被网盘额度反向决定。

## 7. 非功能需求

### 7.1 交付载体

- 云共享是**主进程能力，随应用更新分发**：全量包与增量包都要覆盖到（`update.runner.ts` 那两条路径），不新增服务端发布面。
- 发布时 `version.json` 与 `version-<platform>-<arch>.json` 必须同批更新（现有发布约定）。
- 新增外部依赖：**零**。目录通道用 `fs`，URL 用已有 `axios`，哈希用 `crypto`。这是本期把凭据存储挪出去之后的附带好处——Phase A 不引入任何需要评审的第三方包。

### 7.2 网络行为

| 项 | 要求 |
|---|---|
| 超时 | 连接 10s、单次读 60s；不许配死成无限 |
| 重试 | 只对幂等 GET 退避重试 ≤3；本期没有远端自动重试写 |
| 取消 | `AbortController` + 单任务槽，形态同 `MockPackService.importTask` |
| 并发 | 同一时刻一个备份任务；与恢复/导入互斥（恢复本身走导入那把槽，两个槽不许互相等待） |
| 代理 | 支持显式代理配置（`HTTPS_PROXY` 语义）。**禁止把同步流量走本产品自己的代理入口**：`resolveTarget` 缺 `x-mock-host` 即抛错，本产品不是通用 forward 代理；不可达时提示用户配置外部代理 |
| 请求预算 | 每次备份前把「将写入的文件数 × 平均体积」显示出来，与月度量（1GB）对照；不做后台节流器，因为本期没有后台写 |

### 7.3 隐私与安全

- 只有脱敏内容能上云（C2-2 + C6），且文案不许夸大（C6 最后一条）。
- 本期不存储任何口令/token（1.4 不包含）。若 Q6 裁决要给被订阅端加 token，token 不许进 `local.config.json`——那是整文件重写的明文配置，且用户会当配置备份拷走。
- 远端文件名不含场景名与项目名（6.1）。

### 7.4 可观测与诊断

不依赖服务端埋点（第 8 章本地埋点仍未接入，见 1.3）。每个远端错误自带「远端证据 + 本地阶段」两个字段，日志能还原到哪一步；诊断中心不新增检查项（本期不把它做成链路自检的一部分，避免范围蔓延）。

## 9. 等价类表（开发前冻结，先写测试再写实现）

### 9.1 远端目录/路径

| 维度 | 取值 | 规定 |
|---|---|---|
| 分隔符 | `/`、`\`、UNC `\\nas\share` | 一律走 `path` 模块；UNC 允许（映射盘是真实用例） |
| 场景名 | 中文、空格、emoji、500 字符、Windows 保留名（`CON`/`NUL`） | 文件名只用 `sha1(ruleId)`，等价类不进文件名 ⇒ 这一整列由构造消掉，但**必须有测试证明**它消掉了 |
| 大小写 | 远端文件系统大小写敏感/不敏感 | key 全小写 hex，规避 |
| 超长路径 | >260 字符（Windows 未开长路径） | `remoteWriteFailed` + 提示换浅目录 |
| 只读挂载/磁盘满 | EROFS / ENOSPC | 分别报，都归 `remoteWriteFailed`，但 detail 带 errno |
| 网盘客户端制造的副本名 | `xxx(1).json`、冲突副本目录 | 不在 manifest 里 ⇒ 按 `remoteCorrupted`（清单与实际不符）而不是当额外场景 |
| 符号链接/目录被替换 | — | 读侧只看 manifest 列出的名字，不遍历目录 ⇒ 天然免疫 |
| 中途拔盘 | — | `remoteUnreachable`，不是 `remoteNotFound` |

### 9.2 URL

| 维度 | 取值 | 规定 |
|---|---|---|
| scheme | `http` / `https` | https 默认；http 需界面常驻警示（C4-3） |
| 尾斜杠、`?` 后参数、百分号编码 | `/`、`%20` vs `+`、已编码 vs 未编码 | **原样使用用户输入的 URL，不做二次编码**（二次编码是这类功能最常见的 404 原因）；等价类逐条有用例 |
| 重定向 | 301/302 跨主机（GitHub → CDN 是典型） | 跟随 ≤3 次；跟不到就 `remoteUnreachable` 与 `remoteNotFound` 按实际状态分报 |
| 响应形态 | 裸包 / BizResponse 包裹 / 纯文本 HTML（登录墙） | C4-2 的固定判定顺序；HTML 落 `remoteShapeUnknown` |
| `Content-Encoding` | gzip/br | 交给 axios 默认解压，不自己解 |
| `Content-Type` | `application/json` / `text/plain` / 空 | **不参与判定**，判定只看内容（网盘与静态目录经常给错类型） |
| 体积 | >32MB | 读侧按 `MOCK_SHARE_MAX_FILE_BYTES` 判，超了拒而不落盘 |
| 不可达 vs 不存在 | 超时/断网 vs 404 | 两个码，不许混（用户排查方向完全不同） |

## 10. UI 需求与状态矩阵

**入口（唯一）**：设置 → 新增「Mock 云共享」分区，插在 `<data-backup />` 之后。不做场景右键、不做顶部工具栏按钮、不做子路由页面。

对调研稿「三段式单页」的修正：本产品的设置页是**单页分区的滚动结构**（`Settings.vue` 里四个组件段），`/onboarding`、`/diagnostic` 那种 route 是「一次性任务页」。云共享是「一个配置 + 两个动作」，形态与 `<data-backup />` 完全同构，所以做成分区而不是新页面；**恢复/订阅的预览与结果不另做一套界面，直接把 `MockImportDialog` 的输入源从「选文件」换成「取远端」**（该弹窗的预览/结果两态、冲突三档、跳转、计数口径都已裁决过，重做一套就是把这些裁决重做一遍）。

分区内容：

1. **远端**：通道类型 MiniSelect（关闭 / 本地目录 / 订阅 URL）、路径或地址、`测试连接`、上次备份时间与结果。
2. **备份**：范围说明（恒全部场景，不给选项）、预计写入体积、`开始备份`、进行中禁用 + 浮标、取消。
3. **恢复 / 订阅**：`读取并预览` → `MockImportDialog`（远端源）。

状态矩阵（每一格都要过，R4 已踩过一次）：

| 状态 | 未选择目录 | 目录不可读 | 远端无 manifest | URL 404 | URL 不可达 | 半包/校验不符 | 超长路径 | 暗色 |
|---|---|---|---|---|---|---|---|---|
| 要求 | 分区显示「未配置」+ 引导，不报错 | `remotePathMissing`/`remoteForbidden`，不自动创建 | `remoteNotFound`，提示「这个目录里还没有备份」 | `remoteNotFound` 与下一条**分开报** | `remoteUnreachable` | `remoteCorrupted`，拒读、不改本地库 | 中间省略、保留尾部；路径列不挤掉动作按钮 | 远端状态文字显式用主题色变量，次级信息走 `--van-text-color-2` |

字号跟随、控件等高、截断处 `v-tip`、下拉用 MiniSelect、tag 用 `van-tag plain`——一律沿用已裁决的单源基线，不新增私有尺寸常量。

## 11. 并发、幂等与删除语义

### 11.1 并发

- 备份任务：进程内单任务槽（形态同 `MockPackService.importTask`），第二次触发拿 `shareInProgress` 被拒，不排队。
- 与导入互斥：恢复会占用导入那把槽，云备份那把槽不许在它之上再等一把锁——两把槽各自独立判空。
- 与库内乐观锁分层：`expectedUpdatedAt` 解决的是「同一个人在同一台机器上开两个窗口」；本期不引入「两个人同时写远端同名文件」的自动解决，多进程共享目录由网盘客户端自己决定，本产品只保证**读侧校验和能挡住半包**。

### 11.2 幂等

- 重放同一次备份 = 覆盖同名远端文件，内容未变时先跳过（C2-4），因此「连点两次」与「点一次」在远端结果上等价。
- 恢复走导入管线，天然继承 R4 的幂等口径（合并模式按包内 `recordId` 重放不产生副本，`skip` 档连内容都不动）。

### 11.3 删除语义（本期的核心安全承诺）

本期没有墓碑，因此把方向定死成**单向**：

> **备份 = 用本地覆盖远端；恢复 = 只往本地加，永不删本地。**

即使远端某条记录不存在、某个场景不存在，恢复也不得删除或停用本地对应内容。这条必须是可测断言（AC-C-13），因为它是「误删不会通过云通道放大」的唯一保证。等 Phase C 要做双向同步时，先解决调研稿 5.4 那三条墓碑规则，再谈自动覆盖——不许用「整包覆盖」假装同步。
