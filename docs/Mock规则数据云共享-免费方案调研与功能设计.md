## 1. 结论摘要

1. **「云共享」是三个成本差一个数量级的需求，必须拆开立项。** ① 备份/恢复（单向写 + 手动读）② 多设备双向同步（要冲突、删除墓碑、后台节流）③ 团队分发（一对多只读订阅 + 显式应用）。②比①③贵 3 倍以上，而且②的难点（并发与删除语义）跟「云」没关系，是数据模型问题。**建议本期只做 ①+③，把 ② 推到下一期。**
2. **不做自有云服务，做「自带存储」（BYO）。** 一旦我们自己托管，就同时背上成本、滥用、合规、可用性与「用户真实接口数据存在我服务器上」的定性变化——而「本地优先、数据不上云」正是本产品对 Charles/Postman 最锋利的差异化卖点之一（roadmap 3.4 优势 4）。BYO 形态下：数据主权在用户、我们零运维、方案天然免费。
3. **推荐三条通道 + 一条零成本捷径，全部免费：**
   - **远端目录（含网盘客户端同步目录）**——不需要实现任何网络协议，坚果云/OneDrive/Syncthing 的本地目录就是「远端」，同步与冲突交给客户端；
   - **订阅任意只读 URL**——「共享」的本质是「把一个 `.json` 的地址给别人」，GET 就够，覆盖 GitHub raw、公司内网 http 静态目录；**读路径比写路径便宜得多，却覆盖团队共享 80% 的价值**；
   - **通用 WebDAV**（坚果云 / Nextcloud / 群晖 / MinIO）——真正需要的时候再上，它是唯一在国内稳定、免费、且用户自助的写协议。
   - **被订阅端（本机 8884 暴露只读场景包，见 5.6）**——同局域网协作不用绕任何云，0.5 人日，性价比高于 WebDAV。
4. **免费额度直接决定架构，不是实现细节。** 坚果云免费版 WebDAV 限 600 请求/30 分钟、单次目录列举 750 项、>10MB 的文件不接受条件请求（实测报告，需我方复测）；GitHub Contents API 写上限 1MB。⇒ 三条硬约束：**同步粒度必须是「整包/分场景文件」而不是逐条记录**、**必须节流合并写**、**单文件目标 ≤8MB 并可分片**。这套数字必须写进需求，否则实现阶段会被迫临时决定（R4 的教训）。
5. **写入必须复用 R4 刚定义的导入管线，一条都不许新写。** 包格式（`MockPackV1`）、校验、归一化、指纹重算、缓存失效、上限与迁移闸门全部由 R4 承担；云共享只负责「把字节搬到远端 / 从远端搬回来」。**依赖关系：R4 的 N3（R4C-14/15/17 写入管线与缓存生效）不做完，云同步等于把「导入成功但一条不命中且不报错」这个 bug 再复制一遍。**
6. **估算：本期建议范围 13.5 研发人日 + 2.0 QA**（①+③，含 WebDAV 之外的两通道）；补齐 WebDAV 写通道 +6.0；补齐双向自动同步 +8.0。全做完 27.5，与 roadmap 把「团队云空间」评为「成本很高」一致。

## 3. 免费方案调研

### 3.1 对比表

评估维度按本产品实际约束排序：**国内可达性 > 是否需要我们运维 > 免费额度是否够 > 写并发原语 > 只读分发能力 > Web 版可用 > 平台风险**。

| 方案 | 国内可达 | 我们运维 | 免费额度（2026-11） | 写并发原语 | 只读分发 | Web 版 | 结论 |
|---|---|---|---|---|---|---|---|
| **本地目录 / 网盘客户端同步目录** | 取决网盘 | 无 | 无限（用额度已由客户端消耗） | 交给客户端（含版本/冲突副本） | 差 | 否 | **本期首选**。零协议实现、零鉴权、可离线、可完全卸载 |
| **通用 WebDAV**（坚果云 / Nextcloud / 群晖 / 飞牛 / MinIO） | 坚果云、内网设备稳定 | 无 | 坚果云免费：上传 1GB/下载 3GB 每月，WebDAV 600 请求/30min，单目录单次 750 项，单文件 500MB | 标准有 `ETag`/`If-Match`/`MOVE`，但各家实现参差；坚果云 >10MB 条件读取报 403（需复测） | 弱 | 否（CORS） | **写通道的唯一现实解**，但要按「能力分级」设计，不能假设都支持条件请求 |
| **GitHub Contents API** | 慢且不稳定（`api.github.com` 可用，`raw.githubusercontent.com` 常不可达） | 无 | 认证 5,000 请求/h、匿名 60/h；**写 ≤1MB**；读 1–100MB 仅 raw；仓库单文件 >50MiB 警告、100MiB 拒 | commit SHA 天然乐观锁（`sha` 参数，冲突返回 409） | 好（版本历史 + diff + PR 评审） | 部分 | **适合「团队规则库」而非个人同步**：1MB 上限与 raw 不可达是国内硬伤 |
| **GitHub Gist** | 同上 | 无 | 匿名 60/h；单文件上限未实测（列为待验证） | 无 | 好 | 部分 | 公开 Gist **必须假定被爬虫索引**（token 泄漏的经典来源），只可用于「加密后的分享包」 |
| **Cloudflare R2** | 需绑自定义域名，直连 SNI 不稳定 | **要**（我们出账号、用户出配置） | 10GB 存储、100 万 Class A / 1,000 万 Class B 操作每月，**无出口流量费** | `If-Match` 支持 | 好 | 是 | 额度与定价最适合做官方托管，但要求用户建桶+发密钥 → 只适合「我们代管的官方档」，与「不做自有云」冲突，**列 v2.0** |
| **Supabase**（Storage + Postgres） | 一般，可连但慢 | **要** | 免费 2 项目、DB 500MB、存储 1GB、出口 5GB、**不活跃自动暂停项目** | ETag / RLS | 好 | 是 | 「自动暂停」对桌面工具是致命体验问题（一周不用就得去控制台唤醒），**不推荐** |
| **Firebase / Dropbox / OneDrive / Google Drive** | Firebase、Drive、Dropbox 大陆不可达或极不稳 | 要 | — | — | — | — | **排除**：目标用户打不通 |
| **自建服务端** | 好 | **要** | 无（要花钱） | 自定义 | 好 | 是 | 与「免费」「零运维」同时冲突，**排除**；roadmap 3.4 优势 4 也会一起丢掉 |

### 3.2 由额度倒推的三条架构约束

| 约束 | 依据 | 设计后果 |
|---|---|---|
| **同步粒度 = 场景级文件，不是记录级** | 坚果云 600 请求/30min（≈20 次/分）；5,000 条记录逐个 PUT 直接爆额度 | 一个场景一个 `.json`，一次同步 = 1 次 LIST + N 次 GET/PUT（N=场景数，通常 <10） |
| **写必须节流合并** | 1GB 上传/月 ÷ 单次 5MB ≈ 200 次全量上传 | 改动后合并窗口 ≥60s（可调），或只手动触发；禁止「每次保存即上传」 |
| **单文件目标 ≤8MB，超限分片** | 坚果云 >10MB 条件请求 403；GitHub Contents 写 ≤1MB | 导出时按体积切 `part-1.json/part-2.json`，manifest 记录分片清单；分片阈值 8MB 写进常量单源 |

**推论**：这三条也顺带解决了 R4 遗留的 50MB 大包问题——云通道本来就不该搬 50MB 包，超过阈值就提示「改用本地文件导出」。

## 4. 产品设计

### 4.1 定位原则（先定边界，再定功能）

| 原则 | 具体要求 | 违反后果 |
|---|---|---|
| 默认关闭 | 全新安装不连云、不探测、不后台请求；首次开启在设置页内显式操作 | 与「零遥测」承诺冲突（R4 已因指标埋点翻车过一次） |
| 明文不出本机 | 云端上传**默认强制脱敏**且不提供关闭；要明文只能先本地导出（R4 Q4 已裁决可关） | 云端 = 出本机，比本地导出高一档风险等级，不能沿用同一策略 |
| 可完全离线 | 关闭云共享后，所有既有功能零变化；同步失败不得阻塞 Mock 命中、启动、保存 | 否则「没网就 unusable」，直接毁掉产品定位 |
| 凭证不入库不裸存 | 网盘口令/token 只走系统级安全存储，不可用时**不落盘**，每次启动索取 | 现在 `local.config.json` 是明文整文件重写，绝不能加进去 |
| URL 不带凭证 | 订阅/写入地址里禁止拼接 token（本产品自带代理，请求 URL 会显示在用户记录里） | 自我泄漏：用户抓自己的包就能看到别人的凭证 |

### 4.3 范围

**包含**：远端目录通道（读写）、URL 订阅（只读）、被订阅端（本机只读导出，§5.6）、备份/恢复/订阅应用三个动作、场景级远端布局与 manifest、分片与体积上限、脱敏强制、凭据安全存储、能力探测与错误分类、设置页 UI、i18n 第五组错误码。

**不包含（并写明原因）**：
- 双向自动同步与冲突自动合并——需要先解决删除语义（§2.2）；
- 逐记录同步——额度不允许（§3.2）；
- 云端在线编辑/评论/diff 视图——是协作产品，不是共享数据；
- Web 版云共享——CORS 与文件系统能力不具备；
- 官方托管档位——待用户量与合规口径明确后再议。

### 4.4 交互

**入口（唯一）**：设置 → 云共享。不做场景右键、不做顶部工具栏按钮——与 R4 Q1「入口收敛两处」的裁决同一取向：备份/恢复/订阅是**跨场景的全局动作**，天然属于设置页。

三段式单页：
1. **远端**：通道类型（目录 / URL）、路径或地址、`测试连接`（返回能力等级与远端体积）、`上次同步`；
2. **备份到远端**：范围（当前场景/全部）、是否含录制来源、分片阈值显示、`开始备份`（进行中按钮禁用 + 标题行「查看进度」浮标，沿用 R4C-26 已定的形态）；
3. **从远端恢复 / 订阅**：先「读取并预览」（不落库），列出场景/记录数/与本地差异（新增 N、可更新 M、无变化 K），再让用户选 `跳过 / 更新 / 复制为新记录`——**直接用 `MOCK_PACK_CONFLICT_STRATEGIES`，不新加措辞**。

**状态矩阵**（每个动作都要过一遍，R4 已踩过一次）：

| 状态 | 目录不存在 | URL 404 | 半包/校验失败 | 远端比本地新 | 超长场景名 | 暗色 |
|---|---|---|---|---|---|---|
| 要求 | 错误码 `remotePathMissing`，提示「请先在设置里重新选择目录」，不自动创建 | 与网络不可达分开报（`remoteNotFound` vs `networkUnreachable`） | 报 checksum 不符，**拒绝写入本地**，提示「远端可能被截断」 | 提示本地有更新，需用户确认方向 | 中间省略，路径保留尾部 | 远端状态文字显式用主题色变量 |

**恢复后必须显式提示**：「已恢复 N 条，均未启用」并给跳转——沿用 R4 RK6（导入即劫持真实请求）的处理。

## 5. 技术设计

### 5.1 远端布局

```
appapi-mock/
  index.json                 ← manifest：格式版本、生成时间、场景清单、分片与校验和
  scenes/<场景名sha1前12>.json  ← 一个场景一包，内容就是 MockPackV1 的 rules[0]
  scenes/<...>.part-2.json
```

- **写=先 `.part` 再改名**。目录通道用 `fs.rename`（同分区原子）；WebDAV 用 `MOVE`，`Overwrite: F` 命中已存在则改走「先备份 `.bak` 再 PUT」；不支持 MOVE 的端点退化为直接 PUT，并把该端点标为**非原子**，读侧靠 checksum 拒绝半包。
- **manifest 先写还是后写**：后写。先写场景文件、最后原子替换 manifest，manifest 即提交点；崩溃后重跑覆盖同名片段即可，不产生「manifest 说有、文件实际没有」。
- **校验和**：复用 `crypto.createHash('sha1')`（同 `mock.docs.ts:112-114` 的用法），存 manifest；读回先比对，不符按 `remoteCorrupted` 拒绝。

### 5.2 manifest 内容

| 字段 | 用途 |
|---|---|
| `format` / `version` | 兼容性只认 version；`appVersion` 仅供排查（与 `mock.pack.ts` 同一口径） |
| `createdAt` / `device` | 展示「谁在什么时候备份的」；`device` 为机器名哈希，**不存真实机器名** |
| `scenes[]`：`key`/`name`/`shards`/`bytes`/`sha1`/`records` | 预览阶段不必下载场景正文就能给统计 |
| `redacted: true` | 云端包恒为脱敏；缺失或为 false 的包**拒绝导入**（防止有人手改） |
| `tombstones[]`（Phase C 才写） | 记录 id + 删除时间 + 保留窗口，见 §5.4 |

### 5.3 读回路径

远端字节 → 现有 `previewMockPack` 语义（预览不落库）→ `importMockPack`（校验/归一化/指纹/查重/迁移闸门/缓存失效一条不落）。**本设计不新增任何落库路径**，云共享只多两个动作：`fetchRemote()` 与 `putRemote()`。

验收写法照 R4 的行为规范：**「备份到远端后，在另一台机器恢复，恢复完成的下一个真实请求必须命中，且匹配过程不回读库」**——而不是「调用 bulkDocs / 调用 put」。

### 5.4 删除语义（Phase C 的前置，本期只登记不做）

- 本地删除时，若云共享开启，写一条墓碑（id + deletedAt）到 manifest；
- 墓碑保留窗口默认 90 天，超窗后由「远端整包重算」自然清除；
- 恢复时：墓碑 id 在本地存在且 `updatedAt` 早于删除时间 → 不复活；晚于 → 视为用户有意重建，保留并清除墓碑。
- 本期不做自动双向同步，因此**不做墓碑**——只在文档里钉住「Phase C 开工前必须先解决删除语义」，避免届时用「整包覆盖」假装同步（那会让误删变成静默丢数据）。

### 5.5 凭据与加密

- 网盘口令/token → `safeStorage.encryptString`（Electron 45，Windows 走 DPAPI、macOS 走 Keychain），存 userData 下独立 `.enc` 文件；`safeStorage.isEncryptionAvailable() === false` 时**不降级为明文**，改为「仅本次会话内存持有，每次启动重新输入」。
- 公开端点分享（可选，Phase B 之后）：口令派生 `scrypt` + AES-256-GCM 整包加密，包内不写口令痕迹；UI 必须写明「口令丢失无法恢复」。
- 任何远端请求**必须 https**；内网 http 需在设置里单独勾选并常驻警示文案。

### 5.6 被订阅端（本机即云端）

本产品主进程本来就监听 HTTP（默认 8884），所以「把场景分享给同局域网的同事」不需要任何云：新增一个**只读、需显式开启、可选 token** 的端点导出场景包，同事用 §4.4 的「订阅 URL」填 `http://<他的机器>:8884/...` 即可。

- 复用声明式路由 `addApiInfo`（与 `src/main/router/appmock.router.ts:196` 起的既有端点同一注册方式，PRD 4.4.6 已定此原则）；
- 响应即 §5.1 的场景包，脱敏在组装时完成，与 R4C-07 同一实现；
- 默认**关闭**，开启时常驻显示监听地址；只监听当前配置的 IP；
- 这是同局域网协作的最短路径，成本约 0.5 人日（含在 C-A3 内），**优先级高于 WebDAV**。

### 5.7 网络行为

| 项 | 要求 |
|---|---|
| 超时 | 连接 10s、单次读写 60s（对齐 50MB 量级）；不可配死 |
| 重试 | 仅幂等的 GET 重试，指数退避 ≤3 次；PUT/MOVE 不自动重试，交用户重触发 |
| 取消 | `AbortController` 单例形态（同 `update.runner.ts:25-39`），**同一时刻只允许一个备份任务**（并发上传同名文件比慢更糟） |
| 代理 | 支持显式代理配置（标准 `HTTPS_PROXY` 语义）。**不能让同步流量走本产品自己的代理入口**：`resolveTarget` 缺 `x-mock-host` 头即直接抛错（`src/main/service/proxy.service.ts:367-372`），本产品不是通用 forward 代理；国内不可达时只能提示用户配置外部代理 |
| 错误分类 | 网络不可达 / 认证失败 / 无权限 / 不存在 / 内容损坏 / 版本过高——**六类分别有码有文案**，不能统一「同步失败」 |
