## 1. 结论摘要

- 文件级拆解后 **研发 28.0 人日 + QA 2.5 人日 = 30.5 人日**，是评审原口径 8.5 人日的 **3.3 倍**。差额全部可追溯到具体文件与工程缺口，见第 7.1 节对账。
- **N0 不做完，后面全部返工。** `saveFile`/`selectFile` 从未被渲染层调用过，`fetchFormFile` 对非 `application/json` 的 mimetype 返回 `undefined`，multipart 临时文件无清理——这三件事不修，导入功能连「读到文件」这一步都不成立，而它们不在原评审的 8.5 人日里。
- **单条卡里最贵也最不能省的是 R4C-14～R4C-17（写入管线与缓存生效）**：它们不产出任何用户可见功能，但决定了导入是「能用」还是「导入成功但一条都不命中」。
- 可裁剪到 22.0 人日（第 7.2 节），代价是 AC-R4-04/06/07/08 失去验收对象；Q4 裁决后「脱敏固定开启」不再是可裁剪项。
- 建议按 **N0 前置 → N1 导出 → N3 写入 → N2 校验 → N5 UI → N4 HAR → N6/N7** 的顺序推进，而不是 PRD 的「先导入导出再 HAR」平铺顺序：写入管线是最大不确定性，应尽早压测。

## 3. 角色、估算口径与完成定义

逐卡的归属与合计见第 7.3 节，不在此处重复维护两份清单。

### 3.2 估算口径

- 单位 0.25 人日；含自测与用例编写，不含跨角色联调等待。
- **纯函数与校验按行数量，接线与状态按次数算**——历史上被低估的一直是后者（R1 的 UI 从 3.5 上调到 7.0）。
- 不含：需求变更、发布打包、灰度观察。

### 3.3 统一完成定义（DoD）

每张卡必须同时满足：

1. `yarn test` 全绿，且新增断言**只针对本卡行为**（不做顺带加固）；
2. `yarn check:strict` **不新增违规数**（当前基线未收口，只需不恶化）；
3. `yarn build:web` 通过；
4. 新增错误码同批补 `zh-CN` / `en`，且码表 ↔ i18n 键集断言通过；
5. 新增 `API_URL` 键满足 `api-url.test.ts` 的前缀与逐字断言；
6. 触及主进程常量/归一化/校验的，**用例表在写实现前冻结**并提交，评审只读用例；
7. 未破坏既有单源：不在页面私有样式里重复定义尺寸/色值，不新写 URL/头/指纹解析实现。
